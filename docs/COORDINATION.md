# Координация параллельных сессий

Репозиторий: `andrewforester/your-anima`. Каждая сессия Claude — это отдельный контейнер и своя ветка, общей памяти у сессий нет. Друг о друге они узнают только через этот файл, git, PR и Issues. **Прочитай файл целиком до первой правки.**

## Общие правила

1. **Одна сессия — одна зона.** Зона — это набор путей, которые сессия может менять. Всё остальное она только читает. Зону задаёт задача (Issue или промпт оркестратора).
2. **Одна сессия на экран.** Экран живёт в своём пакете `ui/<screen>/` (`XxxScreen.kt`, компоненты, `XxxScreenTags`), тест лежит в `commonTest/.../ui/<screen>/`. Параллельные экраны не пересекаются.
3. **Мелкие PR и частые мержи `main`.** Перед началом работы и перед каждым PR влей свежий `main` в свою ветку (`git merge origin/main`, без rebase). Долгоживущая ветка — главный источник конфликтов.
4. **Арбитр — CI.** Перед пушем: `./gradlew ktlintCheck :composeApp:jvmTest`. Красный PR не мержим.
5. **Нужно что-то вне своей зоны** — не правь сам. Опиши это в PR или Issue («нужна зависимость X», «нужен токен цвета Y») и продолжай на локальной заглушке.

## Горячие точки

Эти файлы нужны всем, поэтому у каждого один владелец.

| Что | Владелец | Как быть остальным |
|---|---|---|
| `settings.gradle.kts`, `build.gradle.kts`, `*/build.gradle.kts`, `gradle/libs.versions.toml`, модули, CI | Сессия «Каркас» | Просить зависимость в PR/Issue |
| Точки входа: `MainActivity`, `MainViewController`, `wasmJsMain/**`, `App.kt` | Сессия «Каркас» (в `App.kt` стык меняет UI, см. ниже) | Не трогать |
| `ui/theme/**` — цвета, типографика, формы, токены из Figma | Сессия «Тема» | Делается и мержится **до** экранов; экраны стартуют от `main` с темой |
| `ui/components/**` — общие компоненты | Сессия «Тема» (или отдельная «Компоненты») | Новый компонент пока живёт в пакете своего экрана. Если он нужен второму экрану, выносим отдельным PR владельца |
| Строки | Каждый экран — **свой файл** `composeResources/values/strings_<screen>.xml` | Общий `strings.xml` — только для действительно общих строк (название приложения, «Назад»); владелец — «Тема» |
| Картинки и иконки | Префикс по экрану: `drawable/<screen>_*.xml`; общие иконки — `drawable/ic_*` у «Темы» | Не переименовывать чужие ресурсы |
| `data/**` — мок-данные | Интерфейс и модели: сессия «Данные» (если её нет — сессия экрана, первого, кому они нужны) | Моки для одного экрана — в `data/<screen>/` |
| `docs/COORDINATION.md`, `CLAUDE.md`, `.claude/**` | Оркестратор или человек | Предлагать изменения в PR |

Compose Resources собирает все XML из `values/`, поэтому `Res.string.*` работает одинаково для любого файла. Имена ключей начинай с префикса экрана (`home_title`), чтобы они не сталкивались.

## Порядок слияния

1. **Каркас** → `main`.
2. **Тема** (+ общие компоненты) → `main`. Заменяет заглушку `AppTheme` в `App.kt`.
3. **Экраны** — параллельно, каждый от `main` с темой. Мержатся в любом порядке. Кто мержится позже, тот вливает свежий `main` и чинит конфликты у себя.
4. Экран, который становится стартовым, подключается в `App.kt` (заглушка `HomeScreen`).

## Оркестрация

Иногда работу раздаёт не человек, а **сессия-оркестратор**. Она сама не пишет код экранов, она планирует, запускает сессии и следит за ними.

**Цикл оркестратора:**

1. Прочитать этот файл, `CLAUDE.md` и список экранов (Figma или задание человека). Разбить работу на задачи по шаблону выше так, чтобы зоны не пересекались. Показать план человеку и дождаться «ок».
2. Убедиться, что зависимости уже в `main` (каркас, тема). Если нет — сначала запустить их и дождаться мержа.
3. Для каждой задачи: `create_session` с репозиторием, `outcome_branch = claude/<имя>` и промптом-шаблоном. Промпт самодостаточен: новая сессия не видит переписку оркестратора.
4. Записать запущенные сессии в таблицу «Активные задачи» ниже (session id, ветка, зона) и запушить.
5. Следить: `get_session` / `list_events` по сессиям, `subscribe_pr_activity` по их PR, `send_later` — чтобы проверять примерно раз в час. Застрявшую сессию поправить через `send_message` (при необходимости сначала `interrupt_session`).
6. Когда PR зелёный: мерж — только с подтверждения человека. После мержа попросить остальные активные сессии влить `main`. Строку из таблицы убрать, сессию архивировать (`archive_session`).

**Правила оркестратора:**

- Не запускать две сессии с пересекающимися зонами.
- Не больше 3–4 параллельных сессий: каждую надо проверять, конфликты растут нелинейно.
- Горячие точки (тема, build-файлы) — всегда отдельной задачей и **до** экранов, никогда параллельно с ними.
- Решения, которые меняют чужие зоны или правила этого файла, — только через человека.

**Sub-agents vs сессии.** Внутри одной сессии можно запускать sub-agents (инструмент `Agent`). Они делят с сессией контейнер и файлы, поэтому для правок кода — только с `isolation: "worktree"`. Подходят для короткой параллельной работы (поиск, ревью, два независимых компонента). Отдельный PR, долгая работа или своя ветка — это отдельная сессия.

## Решения каркаса (справочно)

- **Пакет:** `app.youranima`. UI-код: `composeApp/src/commonMain/kotlin/app/youranima/ui/**` (например, `app.youranima.ui.theme.AppTheme`, `app.youranima.ui.home.HomeScreen`).
- **Ресурсы:** `composeApp/src/commonMain/composeResources/`, класс `Res` в пакете `app.youranima.resources`.
- **Модули:** `composeApp` (KMP-библиотека: Android, iOS, Wasm, JVM для тестов, плюс web entry point), `androidApp` (тонкая Android-оболочка — AGP 9 не разрешает application-плагин в KMP-модуле), `iosApp` (Xcode, фреймворк `ComposeApp`).
- **Зависимости для UI** — через version catalog: `libs.compose.material3`, `libs.compose.components.resources`, `libs.compose.uiToolingPreview`.
- **Стык:** в `App.kt` приватные заглушки `AppTheme` и `HomeScreen` с пометкой `TODO(ui)`. UI удаляет их и добавляет импорты из `app.youranima.ui.*` — это единственная разрешённая UI-правка в `App.kt`.
- **ktlint** 1.8.0; `@Composable` функции в PascalCase разрешены.
